## 1. 问题现象

| 现象 | 说明 |
|---|---|
| 发 `0x12`（Vx=50 mm/s）车子"很快"地冲出去 | 50 mm/s 只有 5 cm/s，正常应该像蜗牛爬 |
| 手动把轮子往**车头方向**转，编码器计数**变小** | 反馈符号与运动方向相反 |
| `0x0D` 编码器帧里 M2/M4 累计值是大负数 | 前进被记成了负速度 |
| 速度指令和实际速度差 1.58 倍 | 编码器每圈脉冲常数与实际电机不匹配 |

## 2. 根因

速度环是**增量式 PID**，每 10 ms 累加一次输出：

```c
pwm += Kp*(err - err_next) + Ki*err + Kd*(err - 2*err_next + err_last);
```

编码器符号反了以后，误差 `err = 目标 - 实测` 永远消不掉，反而随转速增大而增大，输出在几百毫秒内就顶到 `MOTOR_MAX_PULSE`（3600），占空比约 56%，于是车全速冲出去。

**叠加的第二个问题**：控制板出厂是按 19:1 电机（836 脉冲/圈）标定的，本车是 30:1 电机（1320 脉冲/圈），即使方向对了，实际速度也只有指令的 1/1.58。

## 3. 改动详解

### 3.1 config.h —— 方向宏

放在 `#endif /* APP_RELEASE */` 之后、`#endif /* __CONFIG_H__ */` 之前，发布版和调试版都生效：

```c
/* ==================== 方向校准（纯软件纠正接线方向）====================
 *  1  = 保持原方向
 *  -1 = 反向
 */
#define MOTOR_DIR_M1                (1)
#define MOTOR_DIR_M2                (1)
#define MOTOR_DIR_M3                (1)
#define MOTOR_DIR_M4                (1)

#define ENCODER_DIR_M1              (1)
#define ENCODER_DIR_M2              (-1)   /* ← 本车改动 */
#define ENCODER_DIR_M3              (1)
#define ENCODER_DIR_M4              (-1)   /* ← 本车改动 */

/* 阿克曼转向舵机方向：1 = 角度增大向右转，-1 = 反向 */
#define AKM_STEER_DIR               (1)
```

**为什么用宏**：以后换电机、换接线、装反了只改这一处，不碰逻辑代码，也不会漏改。

### 3.2 bsp_encoder.c —— 编码器方向（核心）

**① 顶部加 include 和方向表：**

```c
#include "protocol.h"
#include "app_motion.h"
#include "config.h"                                   /* 新增 */

/* 编码器方向校准表：1=原方向，-1=反向 */          /* 新增 */
static const int8_t s_encoder_dir[MAX_MOTOR] = {      /* 新增 */
    ENCODER_DIR_M1, ENCODER_DIR_M2, ENCODER_DIR_M3, ENCODER_DIR_M4
};                                                    /* 新增 */
```

**② `Encoder_Read_CNT()` 返回前乘系数：**

```c
static int16_t Encoder_Read_CNT(uint8_t Motor_id)
{
	int16_t Encoder_TIM = 0;
	switch(Motor_id)
	{
	case MOTOR_ID_M1:  Encoder_TIM = 0x7fff - (short)TIM2 -> CNT; TIM2 -> CNT = 0x7fff; break;
	case MOTOR_ID_M2:  Encoder_TIM = 0x7fff - (short)TIM4 -> CNT; TIM4 -> CNT = 0x7fff; break;
	case MOTOR_ID_M3:  Encoder_TIM = 0x7fff - (short)TIM5 -> CNT; TIM5 -> CNT = 0x7fff; break;
	case MOTOR_ID_M4:  Encoder_TIM = 0x7fff - (short)TIM3 -> CNT; TIM3 -> CNT = 0x7fff; break;
	default:  break;
	}

	if (Motor_id < MAX_MOTOR)                                          /* 新增 */
	{                                                                   /* 新增 */
		Encoder_TIM = (int16_t)(Encoder_TIM * s_encoder_dir[Motor_id]);  /* 新增 */
	}                                                                   /* 新增 */

	return Encoder_TIM;
}
```

**讲解：**

- `Encoder_Read_CNT()` 每 10 ms 调一次，返回"这 10 ms 走了几个脉冲"，是**唯一**的编码器数据入口。
- 在入口乘系数，等于把增量反号；`Encoder_Update_Count()` 里的 `+=` / `-=` 逻辑完全不用动，四种车型（`CAR_MECANUM_MAX` / `CAR_SUNRISE` / 其他）都不受影响。
- 乘完再转 `int16_t`：1320 脉冲/圈、最高约 1.2 m/s 时每 10ms 约 26 个脉冲，远不溢出。

### 3.3 bsp_motor.c —— 电机方向（预留开关）

```c
#include "app_motion.h"
#include "config.h"                                    /* 新增 */

uint8_t motor_enable = 0;

static const int8_t s_motor_dir[MAX_MOTOR] = {         /* 新增 */
    MOTOR_DIR_M1, MOTOR_DIR_M2, MOTOR_DIR_M3, MOTOR_DIR_M4
};

void Motor_Set_Pwm(uint8_t id, int16_t speed)
{
    int16_t pulse = Motor_Ignore_Dead_Zone(speed);

    /* 方向校准：按配置翻转，再做限幅 */              /* 新增 */
    if (id < MAX_MOTOR)                                /* 新增 */
    {                                                  /* 新增 */
        pulse = (int16_t)(pulse * s_motor_dir[id]);    /* 新增 */
    }                                                  /* 新增 */

    // 限制输入
    if (pulse >= MOTOR_MAX_PULSE) ...
```

**讲解：**

- 必须放在 `Motor_Ignore_Dead_Zone()` **之后**：死区补偿（±1600）要跟着最终驱动方向走。
- 必须放在限幅**之前**：先翻成最终值再卡 ±3600，避免翻转后越界。
- 原有 M1/M2 的 `pulse = -pulse`（左右镜像）保留不动，这里只是在外层再叠一层可配置方向，两者互不干扰。

### 3.4 app_ackerman.c —— 转向方向（预留开关）

```c
void Ackerman_Steering(int16_t angle)
{
    akm_servo_angle = Math_Limit_int(angle, -AKM_ANGLE_LIMIT, AKM_ANGLE_LIMIT);
    /* 方向校准：AKM_STEER_DIR=1 角度增大向右，-1 反向（见 config.h） */
    PwmServo_Set_Angle(AKM_ANGLE_ID,
                       Ackerman_Get_Default_Angle() + akm_servo_angle * AKM_STEER_DIR);
}
```

**讲解：** `akm_servo_angle` 仍是**逻辑转角**（左负右正），只有送给舵机的物理角度乘了方向系数。这样 `Ackerman_Ctrl()` 里用逻辑角度算左右轮差速的公式不受影响——否则会出现"轮子差速按左转、前轮却打向右"的自相矛盾。

## 4. 符号推导：为什么只反编码器就够

| 符号 | 含义 |
|---|---|
| **P** | 给正 PWM → 轮子往车头转 = `+1`，往车尾转 = `-1` |
| **R** | 轮子往车头转 → 计数增大 = `+1`，计数减小 = `-1` |

速度环稳定的充要条件是 **P × R = +1**（正反馈一定发散）。

- 实测：手转往车头 → 计数减小 ⇒ **R = -1**
- 飞车时车往前冲（否则累计值符号会相反）⇒ **P = +1**
- 所以 P × R = **-1**，正反馈，必然发散

把 R 翻成 +1：

```
P × R = (+1) × (+1) = +1   → 稳定，且正指令 = 前进
```

**如果以后开环发现某个轮子倒转**（P = -1），再翻电机方向：

```
P × R = (-1) × (+1) = -1   → 仍会发散
→ 把 MOTOR_DIR_Mx 改成 -1，P 变 +1，乘积恢复 +1
```

⚠️ 这种情况**只改 MOTOR_DIR，不要动 ENCODER_DIR**。

## 5. 标定记录

### 5.1 编码器每圈脉冲（10 圈法）

架空，手把左后轮转整 10 圈，读 `0x0D` 帧 M2 累计值：

| | M2 累计 |
|---|---|
| 转之前 | 76756 |
| 转 10 圈后 | 89888 |
| 差值 | **13132** |

→ **1313.2 脉冲/圈**，与 `30 × 11 × 4 = 1320` 吻合（0.5% 偏差来自手转圈数）。

> 电机规格书写 "500ppr"，与实际不符：若真是 500ppr，10 圈应累计 **60 万**。
> **以实测为准**，规格书那个数可能是 GMR 传感器内部分辨率或印刷错误。

同时确认 **M4 全程不变** → 左轮确实接 M2，**没有通道交叉**。

### 5.2 副作用（正常现象）

1. 反馈量约为改前的 1/1.58，速度环等效增益下降 1.58 倍，响应可能略变"软"。觉得迟钝或来回晃就用 `0x13` 命令改 PID（写 Flash，不用重烧）。
2. 速度分辨率 = `100 × 204.2 / 1320 ≈ 15.5 mm/s`（每 10ms 一个计数）。目标 50 时 Vx 会在 46～62 之间跳一个刻度，正常。
3. 改前同样发 50 mm/s 实际只跑约 31 mm/s；改完才是真正的 50 mm/s。

### 5.3 电机参数（理论值）

| 项 | 值 |
|---|---|
| 额定电压 / 电流 | 12V / 0.36A |
| 堵转电流 | 3.2A（⚠️ 大于每路 1.5A 保险丝，堵转会跳闸保护） |
| 空载转速 | 366 ± 26 rpm |

| 额定 / 堵转扭矩 | 1 / 4.5 kg·cm |
| 减速比 | 30 |
| 理论最高车速 | 366 rpm × 204.2 mm ≈ **1245 mm/s** |

## 7. 待测参数（明天做）

### 7.1 轮距 `AKM_WIDTH`

**怎么测**：左右后轮**中心到中心**的水平距离（mm）。
没有卡尺就用卷尺量左轮胎内侧到右轮胎内侧，再加一个胎宽。

**改哪里**：`Source/APP/app_ackerman.h` 第 7 行 `#define AKM_WIDTH (191.10f)`

**影响什么**：
1. 转弯时内外轮的**差速比例**（`speed_L = Vx*(1 + W·tanδ / 2L)`）
2. `Motion_Get_Speed()` 里把左右轮速差换算成**角速度 Vz**（里程计要用）

### 7.2 轴距 `AKM_LENGTH`

**怎么测**：**前轮轴心**到**后轮轴心**的距离（mm），沿车身纵向。

**改哪里**：`Source/APP/app_ackerman.h` 第 8 行 `#define AKM_LENGTH (235.37f)`

**影响什么**：
1. 由角速度 `Vz` **反算前轮转角**：`δ = atan(ω·L / v)`（发 `Vy=0` 时走这条路）
2. 转弯时内外轮差速比例

> 如果你在 ROS 侧自己按轴距算好转角、直接发 `Vy`，`AKM_LENGTH` 就只影响差速，
> 差一点点不影响能开，但转弯会轻微搓地。建议还是量准。

## 11. 注意事项

- 编译时 Keil 可能一直开着（旧缓冲区）。**重新打开工程**或让它"重新加载已修改的文件"，否则一保存就会覆盖改动。
- `.bak` 文件不会被 Keil 编译。
- 固件**没有失联超时停车**：串口不来数据就一直按最后速度跑，ROS 节点必须自己做看门狗。
- 转向舵机供电 **6.8V**，本车 SF 数码舵机额定 6.5V，短时可用，别在打死位置长时间保持。
- 每路电机串 1.5A 自恢复保险丝，堵转（3.2A）会跳闸，等几秒自动恢复，属保护动作。
